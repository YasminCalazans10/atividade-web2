Sala de emergência

Seis crises clássicas de quem está começando no Git e no GitHub, com o sintoma, o motivo do susto e o tratamento exato, linha de comando na mão.

✚ Caso 01 · Commit errado

"Comitei e já quero desfazer tudo"

Tratamento

# desfaz o commit, mas mantém suas alterações intactas git reset --soft HEAD~1

Nada foi apagado. Suas mudanças voltam para a "sala de espera" (staging), prontas para um novo commit, mais caprichado.

✚ Caso 02 · Mensagem constrangedora

"Escrevi uma mensagem de commit horrível"

Tratamento

git commit --amend -m "mensagem nova e decente"

Funciona só antes do push. Depois de publicado, reescrever a história pede mais cuidado (e uma conversa com o time).

✚ Caso 03 · Conflito de merge

"Editei sem puxar as mudanças antes"

Tratamento

# traga as novidades do time git pull # abra os arquivos marcados e escolha o que fica git add . git commit -m "resolve conflito"

Um conflito não é um erro, é o Git avisando que duas pessoas mexeram no mesmo lugar. Ele só precisa que você decida quem fica.

✚ Caso 04 · Arquivo sumido

"Apaguei um arquivo sem querer"

Tratamento

# antes de commitar a exclusão git restore nome-do-arquivo

Enquanto não houver commit confirmando o sumiço, o arquivo está só "desaparecido", não morto.

✚ Caso 05 · Pânico geral

"Preciso salvar meu trabalho antes que algo trave"

Tratamento

# o trio básico de sobrevivência git add . git commit -m "descreva o que mudou" git push

Decore essas três linhas. Elas resolvem 80% dos sustos do dia a dia.

✚ Caso 06 · Perdido na branch errada

"Criei uma branch errada e me perdi"

Tratamento

# volte para o caminho conhecido git checkout main # e, se quiser, remova a branch perdida git branch -d nome-da-branch

Branches são só rascunhos paralelos. Trocar de uma para outra não apaga nada do seu trabalho salvo.

Ficha de vocabulário do paciente

Termos que todo iniciante ouve antes de entender, tradução rápida:

repositório (repo)
a pasta do projeto, com toda a história de mudanças guardada.
commit
uma foto do projeto naquele momento, com uma etiqueta explicando o que mudou.
branch
uma linha do tempo paralela, pra testar coisas sem bagunçar a principal.
pull request
o pedido formal de "posso juntar minha branch com a sua?".
merge
o momento em que duas linhas do tempo viram uma só.
clone
copiar um repositório inteiro, com história e tudo, pro seu computador.
